AlmostThere Browser Cookbook

This cookbook is a human-readable guide to how the AlmostThere Browser works and how its main parts are implemented. It is written for future maintainers, contributors, and AI coding sessions that need to understand the system before changing it.

The book is organized as small numbered sections. Each section lives in its own Markdown file:

appdata/cookbook/<two digit section number>_<section title>.md

The goal is not to restate every implementation detail from the code. The goal is to explain the browser as a working system: what enters each layer, what leaves it, which files usually matter, and which invariants should be preserved when fixing bugs.

Current Scope

The current browser is a pragmatic experimental browser, not a standards-complete engine. Its implementation favors:

  • page-agnostic fixes over site-specific patches,
  • readable pipelines over hidden magic,
  • telemetry-backed debugging,
  • focused fixtures for layout and rendering regressions,
  • conservative browser-like behavior when exact standards compliance is not yet possible.

Where This Cookbook Fits

The existing appdata/docs/ files are engineering notes, roadmaps, and debugging records. This cookbook is different: it should read like a guided book. Sections should explain the system step by step, in the order a new maintainer would naturally ask questions.

When adding future sections, prefer:

  • plain explanations before implementation detail,
  • concrete input/output examples,
  • file and module references only where useful,
  • explicit warnings for fragile invariants,
  • short "how to debug this layer" notes at the end of each section.

Rust Shape

The cookbook itself is documentation, but it mirrors the way the Rust workspace is organized: a small set of crates, each owning one part of the browser pipeline.

    number: u8,
    title: &'static str,
    file: &'static str,
}
