Rust Implementation Reference For Non-Code Readers

This section is written for a reader who cannot open the Rust codebase. The snippets are implementation-shaped examples that explain the important data structures and flows used by AlmostThere Browser. They are not a promise that every identifier matches the current source exactly, but they describe the architecture the code should follow.

The browser is easiest to understand as a typed pipeline:

fn navigate(command: NavigationCommand, app: &mut BrowserApp) {
    let tab_id = app.ensure_target_tab(command);
    app.spawn_page_worker(tab_id);
}

fn page_worker(url: String) -> Result<PageOutput, PageFailure> {
    let loaded = load_main_document(&url)?;
    let document = parse_html(&loaded.html)?;
    let stylesheets = load_stylesheets(&loaded, &document)?;
    let computed = compute_styles(&document, &stylesheets)?;
    let script_effects = run_initial_scripts(&document)?;
    let page = apply_effects(document, script_effects)?;
    let layout = build_layout(&page, &computed)?;
    let render_graph = build_render_graph(&layout)?;
    let canvas_scene = build_canvas_scene(&render_graph)?;
    Ok(PageOutput { canvas_scene, discovered_images: layout.images })
}

Browser Application State

The application state belongs to the GUI shell. It knows about tabs, selected tab, preferences, history, pending page messages, and debug options.

struct BrowserApp {
    tabs: Vec<TabState>,
    selected_tab: Option<TabId>,
    preferences: Preferences,
    history: BrowserHistory,
    debug: DebugOptions,
    pending_messages: Vec<PageMessage>,
}

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
struct TabId(u64);

struct TabState {
    id: TabId,
    title: String,
    current_url: String,
    status: TabStatus,
    history: TabHistory,
    scene: Option<CanvasScene>,
    page_id: Option<PageId>,
    zoom: f32,
    scroll: ScrollOffset,
}

enum TabStatus {
    Idle,
    Loading { label: String, progress: f32 },
    Ready,
    Error(String),
}

The shell should only apply page messages to the matching tab and page id. This prevents a slow old navigation from overwriting a newer page.

impl BrowserApp {
    fn apply_page_message(&mut self, message: PageMessage) {
        match message {
            PageMessage::RenderReady { tab_id, page_id, scene } => {
                if let Some(tab) = self.tab_mut(tab_id) {
                    if tab.page_id == Some(page_id) {
                        tab.scene = Some(scene);
                        tab.status = TabStatus::Ready;
                    }
                }
            }
            PageMessage::PageFailed { tab_id, page_id, reason } => {
                if let Some(tab) = self.tab_mut(tab_id) {
                    if tab.page_id == Some(page_id) {
                        tab.status = TabStatus::Error(reason);
                    }
                }
            }
        }
    }
}

Navigation And History

Navigation commands should be explicit data. This lets URL bar input, link clicks, form submissions, bookmarks, history menu entries, and JavaScript navigation share the same path.

enum NavigationCommand {
    OpenCurrent { tab_id: TabId, url: String },
    OpenNewTab { url: String },
    Back { tab_id: TabId },
    Forward { tab_id: TabId },
    Reload { tab_id: TabId },
}

struct HistoryEntry {
    url: String,
    title: String,
    timestamp_ms: i64,
}

struct TabHistory {
    entries: Vec<HistoryEntry>,
    position: usize,
}

Back and forward should move the per-tab history position. Browser-wide history is a separate list used by the history menu.

impl TabHistory {
    fn push(&mut self, entry: HistoryEntry) {
        self.entries.truncate(self.position + 1);
        self.entries.push(entry);
        self.position = self.entries.len().saturating_sub(1);
    }

    fn current(&self) -> Option<&HistoryEntry> {
        self.entries.get(self.position)
    }
}

Resource Loading

The loader turns URLs into bytes and metadata. It should not know about text layout or painting.

AlmostThere uses reqwest as the underlying HTTP/HTTPS library, configured with blocking requests, Rustls TLS, and HTTP/2 support:

reqwest = { version = "0.12", default-features = false, features = ["blocking", "rustls-tls", "http2"] }

The browser should wrap that library instead of spreading reqwest types through the whole application. The wrapper owns browser headers, timeout policy, protocol telemetry, and conversion into browser resource responses.

enum ResourceKind {
    MainDocument,
    Stylesheet,
    Script,
    Image,
}

struct ResourceRequest {
    id: ResourceId,
    page_id: PageId,
    url: String,
    kind: ResourceKind,
    headers: Vec<(String, String)>,
}

struct ResourceResponse {
    id: ResourceId,
    final_url: String,
    status: u16,
    content_type: Option<String>,
    body: Vec<u8>,
    protocol: NetworkProtocol,
}

enum NetworkProtocol {
    File,
    Http1,
    Http2,
}
struct BrowserHttpClient {
    user_agent: String,
    accept_language: String,
}

impl BrowserHttpClient {
    fn fetch(&self, request: ResourceRequest) -> Result<ResourceResponse, LoadError> {
        let response = self.send_with_reqwest(&request)?;
        Ok(ResourceResponse {
            id: request.id,
            page_id: request.page_id,
            final_url: response.final_url,
            status: response.status,
            content_type: response.content_type,
            body: response.body,
            protocol: response.protocol,
        })
    }

    fn send_with_reqwest(&self, request: &ResourceRequest) -> Result<RawHttpResponse, LoadError> {
        todo!("call reqwest, follow configured policy, and record protocol details")
    }
}

The rest of the browser should receive ResourceResponse, not raw reqwest::Response. This keeps the architecture clean: networking belongs to the loading layer, while parsing, styling, layout, rendering, and JavaScript consume browser-owned data.

A more complete HTTP wrapper has three steps: build a stable client, generate browser headers, and translate the response.

impl BrowserHttpClient {
    fn new(user_agent: String, accept_language: String) -> Result<Self, LoadError> {
        let client = reqwest::blocking::Client::builder()
            .user_agent(user_agent.clone())
            .timeout(std::time::Duration::from_secs(30))
            .build()
            .map_err(|err| LoadError::ClientBuild(err.to_string()))?;

        Ok(Self { user_agent, accept_language, client })
    }

    fn request_builder(&self, request: &ResourceRequest) -> reqwest::blocking::RequestBuilder {
        self.client
            .get(&request.url)
            .header("Accept-Language", self.accept_language.as_str())
            .header("Accept", accept_header_for(request.kind))
    }
}
fn accept_header_for(kind: ResourceKind) -> &'static str {
    match kind {
        ResourceKind::MainDocument => {
            "text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8"
        }
        ResourceKind::Stylesheet => "text/css,*/*;q=0.1",
        ResourceKind::Script => "*/*",
        ResourceKind::Image => "image/avif,image/webp,image/png,image/svg+xml,image/*,*/*;q=0.8",
    }
}
fn translate_response(
    request: ResourceRequest,
    response: reqwest::blocking::Response,
    started_ms: u64,
) -> Result<ResourceResponse, LoadError> {
    let status = response.status().as_u16();
    let final_url = response.url().to_string();
    let protocol = match response.version() {
        reqwest::Version::HTTP_2 => NetworkProtocol::Http2,
        _ => NetworkProtocol::Http1,
    };
    let content_type = response
        .headers()
        .get(reqwest::header::CONTENT_TYPE)
        .and_then(|value| value.to_str().ok())
        .map(str::to_string);
    let body = response
        .bytes()
        .map_err(|err| LoadError::BodyRead(err.to_string()))?
        .to_vec();

    Ok(ResourceResponse {
        id: request.id,
        page_id: request.page_id,
        final_url,
        status,
        content_type,
        body,
        protocol,
        elapsed_ms: now_ms().saturating_sub(started_ms),
    })
}

The loader then routes each response by resource kind:

fn route_loaded_resource(page: &mut PageState, response: ResourceResponse) -> Result<(), PageFailure> {
    match response.kind {
        ResourceKind::MainDocument => page.set_html(decode_text(&response)?),
        ResourceKind::Stylesheet => page.add_stylesheet(decode_text(&response)?),
        ResourceKind::Script => page.queue_script(decode_text(&response)?),
        ResourceKind::Image => page.complete_image(decode_image(response.body)?),
    }
    Ok(())
}

For HTTP/2, the browser still uses reqwest for transport. The browser-side concern is tracking per-origin protocol state and choosing a scheduling policy that allows more overlap when HTTP/2 is observed.

#[derive(Clone, Debug, PartialEq, Eq, Hash)]
struct OriginKey {
    scheme: String,
    host: String,
    port: Option<u16>,
}

struct OriginState {
    protocol: Option<NetworkProtocol>,
    in_flight: usize,
    last_started_ms: u64,
}

struct HttpScheduler {
    origins: std::collections::HashMap<OriginKey, OriginState>,
}
impl HttpScheduler {
    fn may_start(&self, origin: &OriginKey, kind: ResourceKind) -> bool {
        let Some(state) = self.origins.get(origin) else {
            return true;
        };

        let limit = match (state.protocol, kind) {
            (Some(NetworkProtocol::Http2), ResourceKind::Image) => 6,
            (Some(NetworkProtocol::Http2), _) => 4,
            (_, ResourceKind::Image) => 1,
            _ => 2,
        };

        state.in_flight < limit
    }

    fn observe_protocol(&mut self, origin: OriginKey, protocol: NetworkProtocol) {
        self.origins
            .entry(origin)
            .or_insert(OriginState {
                protocol: None,
                in_flight: 0,
                last_started_ms: 0,
            })
            .protocol = Some(protocol);
    }
}

The actual protocol is learned from the response version:

fn protocol_from_reqwest(response: &reqwest::blocking::Response) -> NetworkProtocol {
    match response.version() {
        reqwest::Version::HTTP_2 => NetworkProtocol::Http2,
        reqwest::Version::HTTP_09
        | reqwest::Version::HTTP_10
        | reqwest::Version::HTTP_11 => NetworkProtocol::Http1,
        _ => NetworkProtocol::Unknown,
    }
}

The rest of the browser should treat HTTP/2 as an optimization, not as a different content model. HTML bytes are still HTML bytes, CSS bytes are still CSS bytes, and image bytes still go through the image decoder.

HTTP errors, missing files, and unsupported schemes should return typed failures.

enum LoadError {
    InvalidUrl(String),
    UnsupportedScheme(String),
    Network(String),
    Timeout,
    TooManyRedirects,
}

type LoadResult<T> = Result<T, LoadError>;

The parser should preserve source order, text, elements, attributes, and relationships.

    tag: String,

    name: String,
    value: String,

Common helpers should hide raw attribute scanning from later layers.

impl ElementData {
    fn attr(&self, name: &str) -> Option<&str> {
        self.attributes
            .iter()
            .find(|attr| attr.name.eq_ignore_ascii_case(name))
            .map(|attr| attr.value.as_str())
    }
}

Layout Objects

Layout converts document nodes and computed style into rectangles. The important rule is that automatic sizes are often child-aware.

#[derive(Clone, Copy, Debug)]
struct Rect {
    x: f32,
    y: f32,
    width: f32,
    height: f32,
}

struct LayoutBox {
    node_id: NodeId,
    rect: Rect,
    content_rect: Rect,
    style: ComputedStyle,
    children: Vec<LayoutBox>,
    fragments: Vec<InlineFragment>,
}

enum InlineFragment {
    Text { text: String, rect: Rect, style: TextStyle },
    LinkText { text: String, rect: Rect, style: TextStyle, href: String },
    Replaced { node_id: NodeId, rect: Rect },
}

A child-aware sizing pass can be sketched like this:

fn preferred_size(node: NodeId, document: &Document, styles: &StyleMap) -> Size {
    let style = styles.get(node);
    match style.display {
        Display::None => Size::zero(),
        Display::Inline => measure_inline_content(node, document, styles),
        Display::Block | Display::Flex | Display::Grid | Display::InlineBlock => {
            let children = document.children(node);
            let child_sizes = children
                .iter()
                .map(|child| preferred_size(*child, document, styles))
                .collect::<Vec<_>>();
            resolve_container_preferred_size(style, &child_sizes)
        }
    }
}

Canvas Scene And View Transform

The canvas scene is the paintable representation. The view transform maps document coordinates to screen coordinates and back.

struct CanvasScene {
    objects: Vec<CanvasObject>,
    document_size: Size,
}

enum CanvasObject {
    FillRect { rect: Rect, color: Color },
    DrawText { position: Point, spans: Vec<TextSpan> },
    DrawImage { rect: Rect, image_id: ImageId },
    HitBox { rect: Rect, target: HitTarget },
}

struct ViewTransform {
    scroll: Point,
    zoom: f32,
}

impl ViewTransform {
    fn to_document(&self, screen: Point) -> Point {
        Point {
            x: screen.x / self.zoom + self.scroll.x,
            y: screen.y / self.zoom + self.scroll.y,
        }
    }
}

Painting and hit testing must use the same transform.

Copied text should be reconstructed from semantic flow, not from visual line wrapping alone.

fn copy_selection(selection: &Selection, document: &Document, layout: &LayoutTree) -> String {
    let fragments = layout.fragments_in_selection(selection);
    fragments
        .into_iter()
        .map(|fragment| fragment.copy_text())
        .collect::<Vec<_>>()
        .join("")
}

Image Queue

Images are discovered during parsing and layout but may complete after first paint.

enum ImageState {
    Discovered,
    Queued,
    Loading { started_ms: u64 },

    Failed { reason: String },
}

struct ImageJob {
    image_id: ImageId,
    page_id: PageId,

}

struct ImageQueue {
    jobs: VecDeque<ImageJob>,

    cooldown_until_ms: u64,

When a late image completes, the browser applies it only to the matching live page.

fn complete_image(app: &mut BrowserApp, result: ImageResult) {
    if let Some(tab) = app.tab_for_page_mut(result.page_id) {
        tab.update_image(result.image_id, result.state);
        tab.request_repaint();
    }
}

JavaScript Runtime Boundary

JustBarelyScript should produce effects. The browser applies those effects through the normal document/style/layout/render path.

enum JsEffect {
    SetAttribute { node_id: NodeId, name: String, value: String },
    SetInlineStyle { node_id: NodeId, property: String, value: String },
    SetTextContent { node_id: NodeId, text: String },
    AddClass { node_id: NodeId, class_name: String },
    RemoveClass { node_id: NodeId, class_name: String },
    RegisterEventListener { node_id: NodeId, event: String, callback: JsObjectId },
    ScheduleTimer { delay_ms: u64, callback: JsObjectId },
    Console { level: ConsoleLevel, message: String },
}

fn apply_js_effect(page: &mut PageState, effect: JsEffect) {
    match effect {
        JsEffect::SetInlineStyle { node_id, property, value } => {
            page.document.set_inline_style(node_id, property, value);
            page.invalidate_style();
        }
        JsEffect::SetTextContent { node_id, text } => {
            page.document.set_text(node_id, text);
            page.invalidate_layout();
        }
        _ => page.record_pending_effect(effect),
    }
}

The JavaScript runtime should not directly call paint routines.

Telemetry

Telemetry should be structured before it becomes JSONL text.

enum TelemetryEvent {
    NavigationStarted { tab_id: TabId, url: String, at_ms: u64 },
    MainDocumentLoaded { page_id: PageId, status: u16, bytes: usize, elapsed_ms: u64 },
    ResourceFailed { page_id: PageId, url: String, kind: ResourceKind, reason: String },
    ScriptError { page_id: PageId, message: String },

fn write_jsonl(event: &TelemetryEvent, out: &mut dyn std::io::Write) -> std::io::Result<()> {
    let line = serialize_event_as_json(event);
    writeln!(out, "{line}")
}

Every difficult bug should be explainable by a sequence of telemetry events.

Failure And Recovery

Failures should describe the layer that failed and the recovery decision.

enum PageFailure {
    Load(LoadError),
    Parse(String),
    ScriptBudgetExceeded { script_url: Option<String> },
    Layout(String),
    WorkerCrashed(String),
}

enum RecoveryDecision {
    Continue,
    ContinueWithPlaceholder,
    ShowTabError(String),
    StopWorker,
}

fn decide_recovery(failure: &PageFailure) -> RecoveryDecision {
    match failure {
        PageFailure::Load(_) => RecoveryDecision::ShowTabError("Page failed to load".into()),
        PageFailure::ScriptBudgetExceeded { .. } => RecoveryDecision::Continue,
        PageFailure::Layout(message) => RecoveryDecision::ShowTabError(message.clone()),
        PageFailure::Parse(_) => RecoveryDecision::ContinueWithPlaceholder,
        PageFailure::WorkerCrashed(message) => RecoveryDecision::ShowTabError(message.clone()),
    }
}

The main GUI should survive page failures and preserve enough diagnostics to continue debugging.

Practical Reading Rule

If you cannot inspect the codebase, read every Rust snippet as a contract:

  • which data enters the layer,
  • which data leaves the layer,
  • which errors can happen,
  • which ids keep work attached to the right tab or page,
  • which telemetry event proves the step happened.

That contract is more important than any single function name.
