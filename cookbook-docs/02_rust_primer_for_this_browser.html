Rust Primer For This Browser

AlmostThere Browser is written in Rust, so the shape of the code follows Rust's ownership, type, and error-handling model. This section is not a full Rust tutorial. It explains the parts of Rust that matter when reading or changing this browser.

Rust is useful here because a browser pipeline moves structured data through many layers: URL loading, HTML parsing, CSS computation, layout, rendering, JavaScript effects, and GUI state. The compiler helps keep those layers explicit.

Ownership And Borrowing

Rust values have owners. A value can be moved, borrowed immutably, or borrowed mutably. This matters in browser code because the same page data should not be freely mutated by unrelated layers at the same time.

struct PageState {
    url: String,
    title: String,
    html: String,
}

fn page_title(page: &PageState) -> &str {
    &page.title
}

fn replace_html(page: &mut PageState, html: String) {
    page.html = html;
}

The first function reads the page. The second function mutates it. That distinction is a useful design pressure: parsing, style, layout, rendering, and telemetry should each receive the amount of access they actually need.

Structs And Enums

Structs group data. Enums describe one of several possible states. Browser code uses both constantly.

struct Resource {
    url: String,
    kind: ResourceKind,
}

enum ResourceKind {
    Document,
    Stylesheet,
    Script,
    Image,
}

Enums are especially useful because a browser pipeline has many choices: resource kind, display type, script result, navigation command, image status, and page failure mode.

Result And Option

Rust avoids hidden nulls and unchecked exceptions. Option<T> means a value may be missing. Result<T, E> means an operation can fail.

fn resolve_url(base: &str, href: &str) -> Result<String, String> {
    if href.starts_with("http://") || href.starts_with("https://") {
        Ok(href.to_string())
    } else if href.is_empty() {
        Err("empty href".to_string())
    } else {
        Ok(format!("{base}/{href}"))
    }
}

This style fits browser work. Network requests fail, images may not decode, script execution may throw, and a node may not have an attribute.

Pattern Matching

match is how Rust handles enum states clearly.

fn resource_label(kind: ResourceKind) -> &'static str {
    match kind {
        ResourceKind::Document => "document",
        ResourceKind::Stylesheet => "stylesheet",
        ResourceKind::Script => "script",
        ResourceKind::Image => "image",
    }
}

When a new enum variant is added, the compiler can force callers to handle it. That is useful when adding new browser states.

How This Relates To AlmostThere Browser

The browser is a sequence of typed transformations. Rust lets each transformation expose a clear contract: loader output, parsed document, computed style, layout tree, render graph, canvas graph, JavaScript effect, or telemetry event.

When changing code, prefer adding explicit types over passing loosely structured strings or maps between layers. Browser bugs are easier to trace when the type system shows what each layer can produce.
